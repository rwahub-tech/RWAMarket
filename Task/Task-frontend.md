# RWAHub Frontend Test

You will receive access to the existing RWAHub codebase for review.

**Do not make changes directly to our repository.**

Create your own GitHub repository, copy the required project code into it, and complete the task there.

---

## Task

Review the existing RWAHub frontend and make **one meaningful frontend improvement**.

Choose one area that you believe needs improvement, for example:

* Asset marketplace/listing UX
* Asset detail page
* Search/filtering
* Responsive UI
* Wallet connection UX
* Transaction status/error handling
* Loading/error/empty states
* Frontend code structure or component quality

You should focus on **quality rather than quantity**.

Do not rebuild the entire application.

### Security Review

As part of the task, identify **1–2 frontend security issues or risks** you notice in the existing code.

Create:

```text
SECURITY.md
```

For each issue, briefly explain:

* What you found
* Risk level
* Why it matters
* How you would fix it

You do not need to fix every security issue.

---

## Expected Submission

Create your own **GitHub repository** containing your completed work.

Please send:

### 1. GitHub Repository

A link to your repository with the completed implementation.

The repository should contain the actual source code, not just screenshots.

### 2. Loom Video

Record a **5–10 minute Loom video** showing:

* Your implementation
* The main changes you made
* How the feature works
* Security issues you identified
* Brief explanation of your technical decisions

Please send the Loom link together with your GitHub repository.

### 3. Short Summary

Include a short message:

```text
GitHub:
[repository link]

Loom:
[video link]

Summary:
- What I changed
- Why I chose this area
- Security issues identified
- What I would improve next
```

---

## Evaluation

We will review:

* React/TypeScript quality
* Understanding of the existing codebase
* UI/UX quality
* Code structure
* Error handling
* Web3/frontend understanding
* Security awareness
* Ability to make practical technical decisions

**We are not expecting a complete production application.**

The goal is to see how you approach an existing Web3 frontend, make a focused improvement, and explain your decisions.
